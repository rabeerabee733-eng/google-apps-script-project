# تطبيق التحضير الإلكتروني — iPhone وAndroid

تطبيق إدارة أصلي مكتوب بـ React Native وExpo. يستخدم عناصر الهاتف الأصلية، وليس WebView أو PWA. المتصفح يُستخدم فقط لموافقة المدير بحساب Google. نظام Google Apps Script وجدول البيانات الحالي هما مصدر البيانات؛ لا توجد قاعدة طلبات جديدة أو بيانات وهمية.

> حالة التسليم: أُنتج APK تجريبي لـ Android (ARM64، Android 7 فأحدث) واجتاز فحص التوقيع. يستخدم توقيع Android Debug للاختبار الداخلي، وليس توقيع النشر النهائي. أُنتج IPA غير موقع لـ iPhone (iOS 16.4 فأحدث)، جاهز للتوقيع الشخصي عبر AltStore على Windows؛ راجع INSTALL-ALTSTORE.md. لم يُنشر ربط الخادم ولم تُختبر الأجهزة بعد.

## الوظائف المنفذة

- دخول الموظف بالحساب الحالي، وحفظ الجلسة باستخدام iOS Keychain وAndroid Keystore عبر SecureStore. لا تُحفظ كلمة المرور.
- دخول المدير بربط لمرة واحدة: موافقة Google على رمز مطابق، صلاحية الربط خمس دقائق، والجلسة حتى ست ساعات. يمكن إلغاء جميع جلسات المدير من صفحة الربط.
- ملفات أجيال: البحث والتصفية، تعديل بيانات المعلم والصف والملاحظات وحالة الملف، وتسجيل الموظف الذي أنجزه مع منع تعارض التعديلات.
- لوحة أعداد الطلبات وقيمتها وحالاتها، البحث بالاسم والطلب والهاتف وتصفية الحالة، تفاصيل الطلب وتحديث حالته.
- دفعات التجهيز: معاينة نطاق الطلبات وإنشاء دفعة لموظف، فتح طلب بالرقم أو الكاميرا، تدقيق البنود، حفظ التدقيق وإكمال التجهيز. يحافظ الخادم على تعارض النسخ وتكليف الموظف.
- عرض دفعات التوصيل والمبالغ المتبقية وتحديث حالة الطلب، مع سبب الإرجاع أو تعذر التسليم وتحقق تعارض التحديث.
- للمدير: عرض المصروفات والفواتير والرواتب، إنشاء سجل جديد، الخصومات والسلف وأسبابها، تسجيل دفعة فعلية، سجل الدفعات والتعديلات. الحسابات المالية على الخادم بالفلس، ومعرفات العمليات تمنع تسجيل الدفعة نفسها مرتين عند إعادة المحاولة.
- واجهة عربية بالأسود والذهبي والأبيض، اتجاه نص عربي، أحجام متجاوبة، حالات تحميل وأخطاء، منع الضغط المكرر، وعدم إعادة إرسال عمليات الحفظ تلقائيًا بعد انقطاع الشبكة.

## حدود هذه النسخة

هذه أول نسخة أصلية لإدارة العمل، وليست نقلًا كاملًا لكل أدوات لوحة الويب. إنشاء/تعديل منتجات الحجز، تعديل جميع حقول طلب العميل، الحذف والاستعادة، طباعة وتصدير PDF للستكرات، تأكيد تسليم دفعة لشركة التوصيل وتسجيل تحصيلاتها، إدارة حسابات الموظفين وصلاحياتهم والنسخ الاحتياطية، وتعديل/إلغاء السجلات المالية تبقى في لوحة الإدارة الحالية. لا توجد إشعارات دفع أو مزامنة دون اتصال. لا يشمل التطبيق متجر ملفات PDF السابق.

## إعداد الخادم مرة واحدة

1. احتفظ بنسخة من إصدار Apps Script الحالي. انقل `NativeApi.gs` و`NativePair.html` والتعديلات الصغيرة في `PortalAuth.gs` و`الرمز.js` إلى **مشروع Apps Script نفسه** المرتبط بالبيانات الحالية، بعد مراجعة الفرع ودمجه. لا تنشئ مشروعًا منفصلًا لأن ربط الجلسات يحتاج ذاكرة المشروع المشتركة.
2. حدّث نشر API العام الحالي إلى إصدار يتضمن الملفات الجديدة. يبقى `doPost` الخاص بالحجوزات كما هو؛ مسار التطبيق يُختار فقط عند إرسال `mobile=1`. جميع العمليات الحساسة تتطلب رمز جلسة وتفحص الصلاحيات على الخادم.
3. حدّث نشر الإدارة الموثوق. يجب أن يتيح التعرف على حساب Google الفعلي بواسطة `Session.getActiveUser()`، وبما يلائم سياسة نشر الإدارة الحالية. لا تزل قائمة `ADMIN_EMAILS` ولا تستبدلها بحساب يرسله العميل. إذا ظهر رفض لحساب صحيح، تحقق من تنفيذ نشر الإدارة كالمستخدم الذي يصل إلى التطبيق وصلاحياته على الجدول، بدل تخفيف التحقق.
4. استخدم حساب موظف تجريبي محدود الصلاحيات وطلبات اختبار معزولة. لا تستخدم بيانات حية لعمليات اختبار الكتابة.
5. في التطبيق أدخل رابط API العام ورابط نشر الإدارة؛ كل منهما بالشكل `https://script.google.com/macros/s/DEPLOYMENT_ID/exec`، دون معاملات إضافية. الروابط ليست كلمات مرور. لم تُثبّت روابط تلقائيًا حتى لا تتصل النسخة بخادم لم يُحدّث.
6. للموظف: اسم المستخدم وكلمة المرور الحالية. للمدير: اضغط «ربط حساب المدير»، افتح Google، طابق الرمز، وافق ثم عُد واضغط «إكمال الربط». لا تشارك رمز الربط مع شخص آخر.

ملف `.claspignore` يستبعد مجلدات التطبيق والاختبارات من رفع Apps Script. لا تنشر `node_modules` أو مجلدات البناء إلى Apps Script.

## تشغيل وبناء التطبيق

المتطلبات: Node متوافق مع Expo SDK 57 (اختُبر Node 24)، وnpm. ملف القفل يثبّت التبعيات المستخدمة.

```sh
cd native-app
npm ci
npm run typecheck
npm run lint
npm run test:client
npm run test:api
npm run bundle
npm run prebuild
```

`npm run bundle` يجمع JavaScript/Hermes لكلا النظامين؛ **ليس APK أو IPA**. أمر prebuild يولّد مشروعي `android/` و`ios/` من الإعدادات؛ لذلك لا يُحفظان في Git.

### Android

يتطلب JDK 17 أو الإصدار الذي تطلبه أدوات البناء، Android SDK 36، Build Tools 36، وNDK كما تحدده التبعيات. عيّن `ANDROID_HOME` إلى مسار SDK.

```sh
npm run android
```

هذا للتطوير مع هاتف/محاكي. ملف مستقل للتجربة الداخلية:

```sh
npx expo prebuild --platform android
cd android
./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a
```

الناتج `android/app/build/outputs/apk/release/app-release.apk`. إعداد Expo المحلي الافتراضي يوقّع هذا بمفتاح الاختبار؛ **لا تستخدم مفتاح الاختبار للنشر التجاري**. نسخة ARM64 مناسبة للأجهزة الحديثة وليست جميع المعماريات. للإنتاج جهّز مفتاح إصدار يملكه صاحب المشروع واحفظه خارج Git، أو استخدم EAS بملف `production`.

### iPhone

على Mac مع Xcode:

```sh
npx expo prebuild --platform ios
npx pod-install
npm run ios
```

افتح مشروع Xcode الناتج وحدد Team الخاص بك، ثم اختر المحاكي أو الجهاز. التثبيت على جهاز فعلي يحتاج توقيع Apple؛ التوزيع عبر TestFlight/App Store يحتاج عضوية Apple Developer وإعداد App Store Connect. لا توجد شهادة أو مفتاح توقيع مضمنان بالمشروع.

### البناء السحابي الاختياري

بعد إعداد حساب Expo وصلاحيات Apple والموافقة على أي تكلفة:

```sh
npx eas-cli login
npx eas-cli build:configure
npx eas-cli build --platform android --profile preview
npx eas-cli build --platform ios --profile preview
```

ملف `preview` يخرج APK لـ Android وتوزيعًا داخليًا موقعًا لـ iOS، وقد يحتاج تسجيل أجهزة iPhone. `simulator` مخصص لمحاكي iOS ولا يثبت على هاتف. لم يُفعّل حساب EAS أو خدمات مدفوعة تلقائيًا. معرّف الحزمة المبدئي `com.altahdir.management`؛ تأكد من ملكيته قبل النشر. لم يُطلب أو يُحفظ أي مفتاح Apple.

## الخصوصية والعمليات

- الجلسات تُرسل في جسم POST عبر HTTPS، لا في URL. لا توجد تحليلات أو إعلانات أو مشاركة بيانات مع مزود AI.
- بيانات الطلبات والمالية في الذاكرة أثناء العرض فقط، ولا توجد قاعدة بيانات محلية. زر الخروج يمسح الجلسة محليًا ويحاول إلغاءها على الخادم.
- نسخ Android الاحتياطية للتطبيق معطلة، ومفتاح جلسة iOS مرتبط بالجهاز. تظل سياسات نسخ بيانات Google Sheets الحالية مسؤولة عن النسخ الاحتياطي للطلبات.
- التخزين المؤقت في Apps Script قد يُخرج الجلسات قبل ست ساعات؛ عندها يسجل الموظف الدخول أو يعيد المدير الربط.
- عند تغيير صلاحيات الموظف أو تعطيله تتوقف جلسته؛ إزالة المدير من `ADMIN_EMAILS` تمنع استعمال رمزه. إلغاء جلسات المدير متاح من صفحة الربط للمخولين.
- حفظ البيانات المالية يسجّل عمليات تمت بالفعل ولا يرسل أموالًا.

## التحقق قبل الإطلاق

انظر `VERIFICATION.md` للنتائج الفعلية والقيود. يجب تجربة النسخة على هاتف Android وiPhone، اتصال ضعيف، العربية والأسماء الطويلة، إذن الكاميرا ورفضه، الدخول والخروج والربط، وتجهيز طلب اختبار وتحديث توصيله وتسجيل دفعة اختبار. لم تجر اختبارات كتابة على الحسابات أو الطلبات الحية.

تكاليف التشغيل المحتملة: Google Workspace/حصص Apps Script بحسب الحساب والاستعمال، حساب Apple Developer للتوزيع، حساب Google Play إن أردت النشر العام، وEAS اختياري بحسب خطته. البناء المحلي لا يتطلب EAS. لم يتم شراء خدمة أو فتح بيع عام.
